Part 1 - Why this format works

01. Anatomy of a launch video

Pull up any launch video that went viral this year and freeze it every second. You will see the same grammar:

FORMAT    1920x1080 for X and YouTube, 1080x1350 for the feed, 20-35 seconds
HOOK      0-2s: one big word or a question, never a logo
PROBLEM   2-6s: the pain in one line of kinetic type
PRODUCT   6-22s: the real UI, cropped tight, one feature per shot
PROOF     a number that ticks up (users, speed, money saved)
CTA       last 3s: logo lock-up + one line + URL
CUTS      a new shot every 1-2 seconds, on the beat
CAMERA    slow push-ins on UI, never a static screenshot
SOUND     one music bed, soft UI pops on clicks, one hit on the logo

You can run that breakdown yourself on any reference with Claude Code.

Extract the frames first:

ffmpeg -i reference.mp4 -vf "fps=2,scale=640:-2" frames/ref-%04d.jpg

Then paste this:

Analyze reference.mp4 as a FORMAT, not as content to copy.
Report size, fps and duration with ffprobe. Open every frame in frames/.

Save REFERENCE.md with:
- every cut with timestamp
- what is on screen per shot: UI, type, number, logo
- the motion per shot (push-in, slide, mask reveal, counter)
- type: font feel, weight, words per card, where it sits
- where the music hits and what lands on each hit

Label every value MEASURED (read from a frame), ESTIMATED or DECISION.
Never copy logos, copy or brand assets.
End with 5 decisions for our own original video.

02. Why most AI promos look like AI promos

They die in the first second for the same reasons:

  • Centered title on a gradient. The default of every model. Viewers have seen it 1,000 times.
  • Everything fades in. No weight, no anticipation, no overshoot.
  • Fake UI. Generic dashboards with lorem numbers. Your real product is more convincing than any mock.
  • Timing on a timer. Shots change every 2.0 seconds instead of on the beat or on a new idea.
  • Silence or stock whoosh on every cut.

Every step below fixes one of those.

Part 2 - Set up the studio

03. Install only what the video needs

Skills are code that runs with your agent. Open each repo and read it before you install it.

# The renderer: HTML in, deterministic MP4 out (needs Node 22+ and FFmpeg)
claude plugin marketplace add heygen-com/hyperframes
claude plugin install hyperframes@hyperframes

# Animation that doesn't look default: timelines, SplitText, MorphSVG (all free now)
npx skills add https://github.com/greensock/gsap-skills

# Taste: timing, easing, choreography, Disney's 12 principles for UI
npx skills add LottieFiles/motion-design-skill

# Ears: sound effects in code + a launch-film scorecard, CPU only
uv tool install "earshot[mcp] @ git+https://github.com/Leonxlnx/earshot"
earshot doctor --fetch
claude mcp add earshot --scope user -- earshot mcp

What each one is for:

  • HyperFrames turns HTML, CSS and seekable animations into an MP4. Its CLI can lint, take snapshots of any frame and render. It also ships ~450 ready-made blocks: transitions, kinetic type, charts, camera moves. HyperFrames
  • GSAP skills are GreenSock's official skills. They teach the agent real timelines instead of CSS fades. gsap-skills
  • Motion Design Skill makes the agent pick timing and easing before it writes code. motion-design-skill
  • earshot lets the agent hear what it made. Its launch kit preset is built for exactly this kind of film. earshot

04. Write the house rules once

Claude Code reads CLAUDE.md on every run. Put the format in it, so every video starts from the same rules.

# Launch video studio

## Format
- 1920x1080, 30 fps, 20-35 s. Render at exactly this size.
- A new shot on every new idea or beat, every 1-2 seconds.
- Every UI shot moves: slow push-in, slide or mask reveal. No static screenshots.

## Product truth
- Real UI only, captured from the live product. No invented dashboards.
- Every number on screen comes from facts.md. No number, no counter.

## Look
- Brand colours and fonts from DESIGN.md only.
- Big type: max 4 words per card, weight 700+.
- One accent colour for the thing that matters in each shot.

## Banned
- Centered title on a gradient. Logo as the first frame.
- Everything fading in. Same easing on every element.
- A whoosh on every cut. Stock "tech" music with no beat.

## Review before I see anything
1. npx hyperframes check --json, fix every error.
2. Snapshot one frame per second, look at every frame.
3. List the 3 worst problems with timestamps. Fix them. Repeat.

Part 3 - Story first

05. Capture the product, then write 40 words

Start from the real thing. HyperFrames can turn a live URL into an editable project: screenshots become layered scenes and assets are downloaded locally.

npx hyperframes capture https://yourproduct.com -o launch --json

If the result says "ok: false" or there is a BLOCKED.md, stop and capture again. Never build on a half capture.

A 25-second launch video has room for about 40 words on screen. That is the whole budget:

Read the captured project in launch/ and my notes in notes.md.

Write facts.md first: every claim and number we may show, each with where it came from
(the site, the docs, my notes). Nothing invented.

Then write script.md for a 25-second launch video:
- max 40 words on screen in total, max 4 words per card
- card 1 is the hook: the pain or the promise, not the product name
- one feature per card, shown on the real UI
- one proof number that can tick up
- last card: logo + one line + URL

Give me 3 versions with different hooks. Wait for my pick.

Check facts.md yourself. This is the one file you never hand off completely.

06. Turn the script into shots

Split script.md into a shot list. One shot per card, 0.8-2.5 seconds each.

For every shot write:
id, duration, the words on screen
SCREEN which captured screen or crop, and the exact element we zoom into
MOTION push-in / slide / mask reveal / counter, and why
TYPE size, weight, position, which word gets the accent colour
SOUND only if something is clicked, lands or ticks

Then write the key beats in frames at 30 fps, not seconds.

Frames make every edit exact. Here is what one beat looks like:

FRAME  TIME   EVENT
240    8.0s   SHOT 05 starts: dashboard, scale 1.00
246    8.2s   cursor reaches "Generate"
252    8.4s   click: button scales 0.96 -> 1.00 (UI pop on this frame)
258    8.6s   counter starts 0 -> 12,400 over 24 frames, ease-out
282    9.4s   counter lands, accent colour flash
300    10.0s  CUT to SHOT 06

Now "move the click to 250" is an edit the agent can't misread.

Part 4 - Build the scenes in HTML

07. Blocks first, hand-built second

Before the agent hand-builds a transition or a counter, make it check the registry. Someone already debugged it.

Using /hyperframes and /hyperframes-registry, build shotlist.md as one composition.

For every shot, first search the catalog for a block that fits
(kinetic type, counter, mask reveal, camera move, logo lock-up).
Use it and restyle it with DESIGN.md. Hand-build only what has no block.

Animate with GSAP timelines, one timeline per shot, seekable.
Run npx hyperframes lint after the first pass.

08. UI shots: crop tight and move the camera

The fastest tell of a cheap promo is a full-page screenshot sitting still. Treat the UI like footage:

For every UI shot in shotlist.md:
- crop to the one element the card talks about, at 1.6-2.4x scale
- camera: slow push-in, 1.00 -> 1.06 over the whole shot, ease-in-out
- the element that matters gets a soft highlight, everything else dims to 60%
- a cursor only if something is clicked; it moves with an arc, not a straight line
- shadows and corner radius from the real product, never invented

09. Kinetic type with weight

Type carries half the video. Give it rules the model won't break:

Type cards:
- enter with anticipation: 3 frames down 8 px, then up with overshoot (back.out)
- one word per beat, split with SplitText, never the whole line at once
- accent colour only on the word that matters
- exit by being pushed out by the next card, never a fade to black
- stagger 2-3 frames between words, not more

10. The proof number

A number that ticks up is the most watched second of any launch video. Build it right:

Build the proof counter from facts.md:
- tabular (fixed-width) digits so the number never jitters
- 0 -> final value over 20-28 frames, ease-out (fast start, soft landing)
- a soft UI tick every few digits, a hit on the final value
- the unit (users, hrs saved, x faster) appears after the number lands

Part 5 - Sound and render

11. Sound made in code, aimed at the frame

Most AI promos look done with the sound off. Turn it on and the clicks land late and the logo hits in silence.

earshot ships a bank of 252 sound effects stored as code, plus a launch kit preset that mixes every effect against the music bed and says where each one should sit against the cut.

earshot kit init --preset launch -o audio/kit.json
earshot kit render audio/kit.json --out audio/kit

Then hand the cues to Claude in the same frame numbers as the picture:

Using earshot, place the sound for shotlist.md:
- one music bed, the voice of the video; effects sit under it
- UI pop on every click frame, tick on the counter, one hit on the logo
- taps lead the cut, whoosh peaks land just after it
- no effect repeated more than twice in a row

Then run earshot critique on the final mix with the video
and fix every timestamped problem it lists.

The critique scores your film against a profile of 7 professional launch films. It's the closest thing to a sound designer saying "that hit is late".

12. Render and check the file

npx hyperframes check --json                     # lint, runtime, layout, contrast
npx hyperframes render --quality draft -o draft.mp4
npx hyperframes render --quality delivery -o launch.mp4
ffprobe -v error -select_streams v:0 -show_entries stream=width,height,avg_frame_rate,duration -of json launch.mp4

You should see the size, frame rate and duration you planned. Render draft while you iterate and delivery once.

Part 6 - The review loop

13. Make the frames come to you

Never watch the full export ten times. Look at sheets:

# one frame per second, the whole video on one image
ffmpeg -i launch.mp4 -vf "fps=1,scale=320:-1,tile=6x5" -frames:v 1 review/contact.png

# phone test: how it reads at 360 px wide
ffmpeg -i launch.mp4 -vf "fps=1/2,scale=360:-1,tile=5x3" -frames:v 1 review/phone.png

# exact frames around a fix
npx hyperframes snapshot --at 8.0,8.2,8.4,8.6

Then hand the sheets to [advanced model] as a critic, not as the author:

Open review/contact.png and review/phone.png.
You did not make this. You are the harshest motion director I know.

Check: is there any centered title on a gradient? Any static screenshot?
Any card with more than 4 words? Can every word be read at phone size?
Is any number on screen missing from facts.md? Does the first frame
already say why I should care?

List every problem with a timestamp. Fix the 3 worst.
Re-snapshot only those seconds. Show me the new sheet.

Give every correction four fields, so the agent doesn't wander:

WHERE    frames 246-282
PROBLEM  the click pop lands at 256, 4 frames after the button press at 252
CHANGE   only the sound offset: peak of the pop on frame 252
KEEP     the counter, the cut at 300, every other shot

Fix in this order: wrong or missing facts first, then readability, then timing, then visual detail.

14. Package it as a skill

Once the loop works, the next launch is one line:

---
name: launch-studio
description: Make a 20-35 s product launch video from a URL with HyperFrames.
  Use when the user asks for a launch video, promo, feature announcement or teaser.
---

# Launch video

## Pipeline
1. capture the URL. Stop on ok:false or BLOCKED.md.
2. facts.md + script.md (max 40 words, 3 hooks). Wait for my pick.
3. shotlist.md in frames at 30 fps.
4. Registry blocks first, GSAP timelines, real UI only.
5. earshot launch kit, cues on the same frames, earshot critique.
6. check, contact sheet + phone test, critic pass, fix 3 worst, repeat.
7. render delivery, ffprobe check.

## Hard rules
- Every number from facts.md. Real UI only.
- Never copy another brand's video, copy or assets.

Save it as ~/.claude/skills/launch-studio/SKILL.md and call it with /launch-studio.

One URL in. One launch video out. No editor.
